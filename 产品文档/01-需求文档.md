> 版本 v1.0 · 2026-11-15
>
> 范围：Web 端（集团各部门、各基地使用），含主线 10 节点、21 个业务与平台模块、6 项平台能力
>
> 配套文档：[视频解析](./00-视频解析.md)、[业务设计](./02-业务设计.md)、[界面设计](./03-界面设计.md)、[技术方案](./04-技术方案.md)；统一口径见 [README](./README.md) 的「全局统一约定」

## 1. 产品定位

### 1.1 要解决的问题

针织 / 袜业代工企业从接到客户企划到收回货款，要经过 10 个关键环节，涉及业务、技术、品质、计划、采购、生产、关务、财务 8 个以上部门。现状是：

- 信息分散在邮件、Excel、客户平台和个人台账里，进度靠问，一个环节卡住往往难以及时发现。〔视频〕
- 客户企划原件多为英文 PDF，业务员手工摘录、翻译，容易漏项。〔视频〕
- 测试报告能不能复用、报价毛利是否达标、包装执行哪一版，都依赖个人经验，重复送测、版本混用时有发生。〔视频〕
- 各基地产能靠计划部反复收表、人工汇总。〔视频〕
- 物流节点要反复向货代询问；应收「该收多少、什么时候到期、收到没有、谁去催」散落在业务员的个人台账里，往往到月底对账才发现逾期。〔视频〕
- 不同客户的服务流程、单证要求、规则口径差异很大，系统很难统一。〔视频〕

### 1.2 目标用户

集团内部员工：业务员、业务经理、业务总经理，以及技术（打样）、品质（测试与验货）、计划、采购、生产跟单、关务单证、财务、系统管理员。客户、工厂外协方不直接登录本系统（与客户系统的数据交换走数据同步，见 8.5）。〔推断〕

### 1.3 价值

| 目标 | 含义 | 落在哪里 |
| --- | --- | --- |
| 进度看得见 | 每一单走到哪个节点、谁负责、耗时多久、比平均慢多少，一眼可见 | 订单监控、各单据进度时间线、今日待办 |
| 协作接得上 | 上一环节完成自动给下一环节下达任务，跨部门不靠催 | 节点自动流转、待办、通知 |
| 交付管得住 | 闸门把关、巡检预警、逾期当天提醒，问题在出货前、回款前暴露 | G1 / G2 闸门、业务巡检、催收工作台 |

### 1.4 核心链路

```text
客户企划原件 → AI 抽取与翻译 → 业务确认（款主数据）
  → 打样（多轮、5 阶段）→ 寄样 → 客户批复
  → 第三方测试（报告复用校验）→ 报价（成本汇总 + 策略 + 护栏）
  → ◆ G1 开发移交（五项齐套，冻结）
  → 客户 PO 识别 → PO 复核（规则包）→ 待排产（产能台账）
  → 辅料采购与包装方案 → 生产进度
  → 初验 / 中验 / 尾验 → ◆ G2 放行（三条件）
  → 订舱 → 装箱 → 开船 → 到港 → 签收
  → 应收 → 催收 → 回款
```

## 2. 范围

### 2.1 部署形态

- 单企业私有化部署：一套系统服务一个集团，下设多个事业部、多个生产基地（含海外基地），不做多租户 SaaS。〔推断〕
- 只做 Web 端，适配桌面浏览器；不做移动 App，手机浏览器可查看待办和看板但不保证完整操作体验。〔推断〕
- 多法人：一个集团下有多个结算主体 / 工厂主体（如国内主体、海外主体），应收、订单按主体区分。〔视频：结算主体、工厂主体字段〕

### 2.2 行业假设

| 假设 | 说明 | 来源 |
| --- | --- | --- |
| 产品 | 针织袜类为主（童袜、女袜、男袜、运动袜、无缝针织），按双计量 | 视频 |
| 客户 | 海外品牌与零售商为主，单个大客户每年数百款，多币种结算 | 视频 |
| 模式 | 来样 / 来企划开发 → 打样 → 报价 → 接单生产（OEM / ODM），FOB 为主 | 视频 |
| 产能核心维度 | 针型（96N / 120N / 144N 等）× 基地 × 周 | 视频 |
| 外部机构 | 第三方检测机构（BV、SGS 等）、第三方验货平台、货代、船司 | 视频 |
| 内部系统 | 已有纺织服装 ERP（如环思），本平台不替代 ERP 的财务账、库存账 | 视频 |

### 2.3 首版做 / 不做

**首版做：**

- 主线 10 节点全部单据与订单监控；G1、G2 闸门；〔视频〕
- 企划原件 AI 抽取与翻译、客户 PO 识别；〔视频〕
- 今日待办、全局搜索、通知；〔视频〕
- 6 项平台能力：智能助手、客户流程配置、业务自动巡检、多角色看板、主数据适配器、权限与安全；〔视频〕
- 7 套主题、简体中文与英文；〔视频〕
- 主数据管理、操作日志、关键变更回退。〔推断〕

**首版不做：**

- MES 级生产排程（机台级排产、计件）：节点 N08 只做进度登记；〔推断〕
- 财务总账、成本账、库存账：以 ERP 为准，本平台只做业务口径的应收与催收；〔推断〕
- 客户 / 供应商门户（外部登录）；〔推断〕
- 视频里标为「待建页」的 TNA 与预警管理、合规与证书、会议与决策（见第 11 节）；〔视频〕
- 移动 App。〔推断〕

## 4. 全局规则

### 4.1 单号

- 所有内部单号按 README 表 C 生成，前缀与格式全局唯一，生成后不可修改。〔视频：样例；推断：统一规则〕
- 客户侧编号（款号、客户 PO 号、客户参考号、检测机构报告号）原样保存，不改写、不补前缀。〔视频〕
- 款以「客户 + 款号 + 季节」唯一；同一款号跨季节视为不同款，但可「沿用上季资料」。〔推断〕
- 单号在全局搜索、AI 助手、巡检判定说明中都可点击跳转到详情。〔推断〕

### 4.2 时效与超期

- 每个流程节点、打样阶段、订单阶段都记录**开始时间、完成时间、实际用时**，并与**平均办结时长**比较；慢于平均时标「慢于平均」。〔视频〕
- 平均办结时长 = 近 90 天同客户（无样本时取全部客户）、同工厂、同阶段已完成记录的平均用时，每日重算。〔推断〕
- 时长按自然日计；打样阶段等短周期以小时显示（如「实际用时 10 小时」）。〔视频：显示粒度；推断：计算口径〕
- 「要求日期」「交期」默认按自然日；客户流程配置里可把某类规则改为工作日（按集团工作日历，含法定节假日与调休）。〔推断〕
- 超期文案统一：已逾期显示「任务逾期 N 天」/「超期 N 天」，当天截止显示「今日 18:00 截止」，次日显示「明日截止」。〔视频〕
- 所有阈值（如打样轮次停留 7 天、客户批复等待 5 天）都在巡检规则或客户规则包里配置，不写死在代码里。〔视频：阈值；推断：可配置〕

### 4.3 版本与客户确认

- 需要客户确认的单据（企划、包装方案、报价、PO）都有版本号；客户确认后锁定，再修改只能生成新版本，旧版本只读可查。〔视频：包装方案 v3、PO 版本 Rev.1、改版日期〕
- 每个版本记录：谁在什么时候改了什么（字段级前后值）、客户是否确认、确认人与确认方式（邮件 / 客户系统 / 线下），并可上传确认凭证。〔视频：旁白「谁在什么时候做了修改都有记录可查」；推断：确认凭证〕
- 同一业务对象任一时刻只有一个「当前执行版本」，下游单据（装箱单、验货单）只能引用当前执行版本。〔视频：旁白「当前执行哪一版」〕
- G1 移交后的开发资料冻结，修改需走变更申请并经 R003 审批，变更后自动通知下游。〔视频：移交后冻结；推断：变更流程〕

### 4.4 多币种与汇率

- 支持 USD、EUR、JPY、CNY 等多币种，单据保存原币金额；看板汇总统一折算为本位币 CNY，显示「万元」。〔视频〕
- 报价使用**锁汇**：报价单记录锁定汇率，人民币成本按锁汇换算外币报价，之后汇率变动不影响已报价格。〔视频：锁汇 6.5 / 6.72〕
- 看板折算使用主数据汇率表的月度汇率；汇率由财务维护或从 ERP 同步。〔推断〕
- 金额显示带币种代码，千分位，外币保留 2 位小数，单价保留到 0.01（元/双、$/双）。〔视频〕

### 4.5 多语言

- 首发简体中文（zh-CN）与 English（en-US），预留越南语（vi-VN）；登录页和顶栏都可切换，选择随账号保存。〔视频：中英切换；推断：越南语〕
- 只翻译界面文案；业务数据（客户名、款名、单号、备注）不翻译，中英文名分别存字段（如款的中文名称、英文名称）。〔视频〕
- 日期、数字、货币格式随语言切换；时区按用户所在地显示，存储统一用 UTC。〔推断〕

### 4.6 附件与原件留存

- 客户企划原件、PO 原件、测试报告、验货报告、确认邮件、提单等原件全部留存，与单据关联，可预览、可下载。〔视频：原文与图片同步保留〕
- AI 抽取出的字段保留「原文出处」（原件页码与原文片段），便于核对。〔推断〕
- 单个附件上限 50 MB；支持 PDF、Excel、Word、图片、邮件（.eml / .msg）。〔推断〕
- 附件不可物理删除，只能作废，作废记录留痕。〔推断〕

### 4.7 操作留痕

- 所有新增、修改、删除、状态变更、导出、权限变更都记录操作日志：操作人、时间、对象、动作、字段前后值、来源（页面 / AI 助手 / 同步任务 / 巡检）。〔视频：数据操作都有记录〕
- 关键变更可回退（如误改的交期、误删的明细），回退本身也记日志；哪些属于关键变更见业务设计 11。〔视频〕
- 每张单据详情页底部有「状态流转」或「操作日志」区块。〔视频：验货详情状态流转、同步任务操作日志〕

### 4.8 全局搜索

- 顶栏搜索框可搜订单号、客户、款号，以及其他内部单号；结果按单据类型分组，回车进入第一条。〔视频：「搜索订单号、客户、款号…」；推断：分组〕
- 搜索结果按当前用户权限过滤。〔推断〕

### 4.9 通知

- 顶栏铃铛显示未读数，点开为通知列表（待办派发、即将到期、巡检红灯、客户确认、@我、同步失败）。〔视频：铃铛角标；推断：通知类型〕
- 首版站内通知 + 邮件；预留企业微信 / 钉钉 / 飞书机器人渠道。〔推断〕
- 用户可在个人设置里按类型关闭邮件通知，红灯与逾期提醒不可关闭。〔推断〕

### 4.10 待办的产生与关闭

- 待办来源：流程节点下达的任务、巡检命中派单、催收下次跟进日、台账更新任务、他人指派。〔视频：巡检「待办事项指派到人」；推断：其他来源〕
- 业务待办由业务动作关闭（如登记验货结果后自动完成），不能手工勾掉；手工创建的待办可手工完成。〔推断〕

## 6. 主线 10 节点

### 6.1 通用规则

- 主线以**客户订单（PO）**为单位展示 10 个节点；PO 生成前，以**款**为单位展示 N01–N05。〔视频：按订单号查看；推断：PO 前按款〕
- 一张 PO 含多个款（如「#11506 等 5 款」）时，N01–N05 取所有款中最慢的状态：全部款完成才算完成；展开节点可看每款的状态。〔视频：多款 PO；推断：聚合规则〕
- 节点状态：待启动 / 进行中 / 已完成 / 受阻 / 不适用。客户流程配置未启用该节点对应服务模块时为「不适用」，不阻塞后续节点。〔视频：前三种；推断：后两种〕
- 节点卡片显示：序号、节点名（闸门节点带 ◆）、状态标签、一行进度说明（含关键单号、责任方、当前事项）、「去处理 →」。进行中的节点高亮。〔视频〕
- 每个节点记录开始、完成时间和耗时，并与平均办结比较。〔推断〕

### 6.4 G2 验货放行「三条件」

## 10. 首版验收标准

### 10.1 主线场景：一张 PO 从企划到回款

以一个虚构客户、一款新款中筒袜为例，在系统中依次完成，且每一步都能在订单监控里看到对应节点状态变化：

1. 业务员上传英文企划 PDF，2 分钟内企划变「提取完成」，中文译文、产品属性、款式图齐全，原文可对照；确认后变「已确认」。
2. 系统自动生成打样单（已下达），技术员推进 5 个阶段，每阶段显示实际用时与平均办结；寄样后登记客户批复「已批准」。
3. 申请送测时系统提示已有可复用报告的项目；新送测项目从寄样到出报告到归档，报告有效期关联到款。
4. 报价单自动汇总成本，套用策略算出内部报价；故意把客户报价调到护栏以下，系统拒绝生成；正常报价第 2 轮被客户接受。
5. 开发移交检查五项，缺 QRS 时不能移交；补齐后移交，资料冻结。
6. 上传客户 PO，系统识别字段并关联到款；规则包全绿，一键推进到「待排产」；产能台账显示该针型空余产能。
7. 用料需求生成采购单；包装方案 v1 经客户确认；修改一次生成 v2，v1 只读。
8. 生产进度登记到 100%，装箱单按包装方案自动算出箱数。
9. 中期验货不合格 → 整改复验合格；尾验合格；测试报告有效；包装已确认 → 登记放行成功。把报告有效期改为已过期后再放行，系统拒绝并说明原因。
10. 订舱、装箱、开船、到港、签收依次登记；签收后自动生成货款应收单。
11. 应收到期当天出现在催收工作台；记录催收；登记部分收款后状态「部分收款」，收齐后「已收款」，订单监控 10 / 10 完成。
