# i18n

## 技术栈

- `i18next` + `react-i18next`
- `i18next-browser-languagedetector`（可选，通过 `useDetector` 开关）
- 自研的 `local-backend`，资源随构建打包

## Namespace 结构

| Namespace   | 用途                                                           |
| ----------- | -------------------------------------------------------------- |
| `common`    | 全局通用（导航、动作、状态、表格、分页、主题、语言、命令面板） |
| `auth`      | 登录、登出、鉴权提示                                           |
| `errors`    | 网络 / HTTP / 业务 / 路由 / 错误页                             |
| `<feature>` | 每个 feature 一个 namespace（例如 `users`）                    |

Key 格式：`{namespace}:{section}.{subKey}`

例：`users:list.title`、`common:action.save`、`errors:notFound.description`。

## 类型化 key

`src/lib/i18n/types.d.ts` 通过 module augmentation 把 `zh-CN` 的 JSON 变成 `i18next.CustomTypeOptions.resources`：

```ts
declare module "i18next" {
  interface CustomTypeOptions {
    defaultNS: "common";
    resources: {
      common: typeof common;
      auth: typeof auth;
      errors: typeof errors;
      users: typeof users;
    };
  }
}
```

新 key 在 zh-CN 加了以后 IDE 立即有补全；漏了在 en-US 加会因为 fallback 到 zh-CN 而不出错但会显示中文，因此约定所有 locale 保持同构。

## 添加新 key

1. 在对应 namespace 的 zh-CN JSON 里加 key
2. 补 en-US 同一 key 的英文文案（zh-CN 与 en-US 必须结构对齐）
3. 若 namespace 是新加的，去 `src/lib/i18n/local-backend.ts` 的 `i18nNamespaces`、`localResources`、`AppResourceMap` 都加上，并在 `types.d.ts` 里 augment

## 硬编码检查

CI 之前应跑 lint。lint 不会捕获所有硬编码，但项目约定：**任何用户可见文案必须 `useTranslation()` 输出**。新写文案 → 直接进 JSON。

## 请求头联动

`src/lib/i18n/i18n.ts` 里调用 `setLocaleGetter(() => i18n.language)`，让请求层的 `X-LANGUAGE` header 永远与当前 UI 语言一致。切换语言（`i18n.changeLanguage(...)`）后下一次请求会自动带新 header。
